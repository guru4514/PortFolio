01 / THE CONTEXT

A problem worth
working through.

The problem

A camera feed is only raw input. A useful prototype needs to extract interpretable measurements, track a changing state, and expose the result where a person can see what the detector is doing.

The approach

OpenCV and facial landmarks provide eye aspect ratio (EAR) and mouth aspect ratio (MAR) measurements. Flask serves the video stream and status. A TensorFlow CNN can optionally add eye-state classification when its model file is supplied.

02 / HOW IT WORKS

A continuous frame-to-state pipeline.

Follow the path through the application.

STEP 01 / 04

Capture a frame

The backend reads from a local webcam. Camera access and the runtime environment are prerequisites.

STEP 02 / 04

Find landmarks

Facial landmarks provide the eye and mouth geometry used by the baseline detector.

STEP 03 / 04

Interpret state

Geometric measurements drive the baseline. A supplied CNN artifact can add eye-state classification.

STEP 04 / 04

Show the signal

The dashboard presents the live stream, detector measurements, and alerts.

03 / THE DECISIONS

The choices
inside the code.

01

Keep the baseline explicit

The documented default path uses EAR and MAR geometry. The application can run without the optional CNN model, so model availability does not prevent trying the baseline workflow.

THE TRADEOFF

Geometry remains sensitive to pose, camera position, and landmark quality. A working baseline is not evidence of reliability across all conditions.

02

Expose the measurements, not just an alarm

The dashboard combines the camera view with measurements and alerts. The status endpoint makes the detector state available separately from the MJPEG video stream.

THE TRADEOFF

Measurements help explain what happened, but they still need context about thresholds and operating conditions.

03

Keep model training separate from live inference

The repository documents an optional training path and the expected model artifact location. The live backend consumes the model only when it is available.

THE TRADEOFF

Reproducing model behavior requires the training data, environment, and saved artifact—not just the application code.

06 / SCOPE & NEXT STEPS

Good engineering
leaves room to improve.

The current scope is a local webcam prototype. Lighting, head pose, camera quality, and threshold choices influence the detector, making a repeatable evaluation across those conditions the next substantial engineering task.

WHAT WOULD MAKE IT STRONGER

The clearest next step is a reproducible evaluation across lighting and pose conditions, including false alarms, missed events, and measured latency on named hardware.
